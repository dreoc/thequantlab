3D geometric morphometrics in R
GUImorph: an rgl-independent, geomorph-native 3D digitizer

GUImorph is an R package with a graphical interface for 3D geometric morphometrics. You load PLY mesh specimens, place landmarks, anchors, and surface semilandmarks, run a Procrustes fit through geomorph, and carry the aligned coordinates on into your analysis. This page walks a first-time user through the whole workflow, one action at a time.

Geometric morphometrics turns the shape of an object into coordinates that can be measured and compared. For a Folsom point, that means recording the same anatomical landmarks and a dense set of surface points on every specimen, then aligning them so that only shape differences remain. GUImorph is built to make that recording step approachable, and to keep it entirely inside R.

The need is concrete. As of geomorph 4.1, the interactive 3D digitizing functions (digit.fixed, digitsurface, buildtemplate) are deprecated, because rgl and OpenGL are no longer supported on current macOS. GUImorph keeps that template-based surface-semilandmark workflow available through its own native OpenGL engine, and feeds results straight into geomorph. There is no separate application to install and no file conversion between programs.

GUImorph 0.9.0 Windows: supported macOS / Linux: not yet
Which computer to use. This beta runs on Windows only. The 3D view uses a native OpenGL component (tkogl2.dll) that is not built for macOS or Linux yet, which is the same OpenGL limitation that ended geomorph's own digitizer. A cross-platform, browser-based version is the longer-term plan. Everything below assumes Windows 10 or newer.

What you will do

The workflow follows the tabs in the GUImorph window, in order, with a few File-menu steps for loading and saving. Here is the whole thing at a glance.

  1. Install R, then install the GUImorph package and launch it.
  2. Prepare your PLY meshes (remove stray and origin points).
  3. Load your first specimen from the File menu.
  4. Learn to rotate, zoom, place, and delete in the 3D view.
  5. Place the fixed landmarks on the 3D Digitizing tab.
  6. Place anchors on the Anchors tab, if you need them.
  7. Build the surface template on the Surface Sliders tab.
  8. Downsample every specimen against that template.
  9. Save each specimen to a .dgt file.
  10. Merge the .dgt files into one dataset.
  11. Run the Procrustes fit on the GPA tab, then plot.
  12. Continue the analysis in geomorph.

Part 1 · Before you start

Install R

GUImorph runs inside R. Install 64-bit R 4.4 or newer (its geomorph dependency requires it). On Windows the quickest way is winget in a terminal, or download the installer from CRAN.

# In a Windows terminal (PowerShell or Command Prompt):
winget install -e --id RProject.R

Restart your terminal after installing R. RStudio is optional but convenient.

Install the GUImorph package

You have the GUImorph Windows package, a single .zip file. It already contains the OpenGL engine, so nothing needs to be compiled. Save the file somewhere you can find it, then run the command below in R, editing the path to match where you saved it.

# Install the GUImorph Windows package, and its CRAN dependencies.
# Edit the path to wherever you saved the file.
install.packages(
  "C:/Users/you/Downloads/GUImorph_0.9.0.zip",
  repos        = "https://cloud.r-project.org",
  dependencies = TRUE
)

# Load it. Do this once at the start of every session:
library(GUImorph)   # prints a banner, e.g. "Using geomorph 4.1.1"

Giving a real repos and dependencies = TRUE lets R install GUImorph's required packages from CRAN for you: geomorph, rgl, Rvcg, Morpho, vegan, and tcltk2. The first install can take a few minutes.

The banner prints (for example Using geomorph 4.1.1) with no loading tkogl2 failed warning.
Tip

For verbose diagnostics at any time, launch with GUImorph(debug = TRUE) instead of GUImorph(). The console is quiet by default.

Installing in RStudio, or installing the dependencies by hand

In RStudio you can install the package file through the menu: Tools ▸ Install Packages, set Install from to Package Archive File (.zip), and pick the file. That route does not install dependencies, so install them first:

install.packages(c("geomorph", "rgl", "Rvcg", "Morpho", "vegan", "tcltk2"))

Prepare your meshes

GUImorph reads PLY surface files. Export your scans as .ply with per-vertex color kept. Before digitizing, remove junk points from each mesh. Scanner exports (for example from NextEngine or ScanStudio) usually carry unreferenced vertices that belong to no face, and null vertices sitting at the exact origin, the point (0, 0, 0). These points are invisible while you work, but they land far from your specimen and become extreme outliers once you run the Procrustes fit. One uncleaned mesh can distort the alignment of the whole dataset.

Do thisIn MeshLab, open each mesh and run Filters ▸ Cleaning and Repairing ▸ Remove Unreferenced Vertices, then Remove Duplicate Vertices. Delete any vertex sitting at the origin. Keep all faces and colors. Export back to .ply.
Common mistake

Skipping this step. It is the single most frequent reason one specimen looks wildly wrong in the final plot. If a mesh includes a vertex at exactly (0, 0, 0), remove it before you digitize.

Part 2 · The digitizing workflow

Work through these in order. Each step names the tab or menu to use, tells you what to do, and tells you how to know it worked.

1

Launch GUImorph

With the package loaded (see Part 1), the interface opens from the R console.

GUImorph()

The 3D GUImorph window opens. On the left is a large dark panel, the 3D view, empty until you load a specimen. On the right is a set of tabs: 3D Digitizing, Anchors, Surface Sliders, Curves, and GPA. You will move left to right through those tabs as you work.

The window is open and you can see the File menu and the tabs on the right.
2

Load your first specimen

Open one of your cleaned meshes from the File menu.

MenuFile ▸ Load PLY File…, then choose one of your .ply files.

Your specimen appears in the 3D view, in its scanned color. If it looks small or off-center, that is fine. You orient it in the next step.

Adding more specimens later

To bring another mesh into the same working session, use File ▸ Add PLY to Current DGT…. To reopen a session you saved earlier, use File ▸ Load DGT File….

Your specimen is visible in the 3D panel, not blank or black.
3

Learn the 3D view controls

Before placing any points, learn how to move the specimen and how points are placed. All four actions happen with the mouse, directly on the 3D view.

RotateDrag with the left mouse button held down.
ZoomScroll the mouse wheel in and out.
Place a pointDouble-click directly on the surface.
Delete a pointRight-click on the point you want to remove.
Tip

Rotating the specimen does not move the points you have already placed. They stay locked to the surface. Turn the specimen freely to check your points from every angle.

You can turn and zoom the specimen, and you know double-click places and right-click deletes.
4

Place the fixed landmarks

3D Digitizing tab

Fixed landmarks are your numbered anatomical points, the same points in the same order on every specimen. This defined order is what lets you compare specimens later, so decide your landmark scheme first and follow it exactly.

Do thisOpen the 3D Digitizing tab and set the number of landmarks. Then double-click each landmark on the surface, in order: 1, 2, 3, and so on. Markers appear in red. To remove one, right-click it.

GUImorph tracks your progress. Once every fixed landmark is placed on a specimen, that specimen is ready for the Procrustes fit.

Tip

Zoom in before placing a precise landmark. A point placed while zoomed out can be off by more than you expect. Rotate the specimen afterward to confirm the marker sits where you intended.

All fixed landmarks are placed, in order, in red, each sitting on the surface.
5

Place anchors: capturing features the downsample would miss

Anchors tab · optional

This step is worth understanding, because it is the one place your judgment corrects the automatic sampling. Surface points are not placed by hand. In the next step, GUImorph builds a template by running k-means over the specimen's full point cloud and keeping a representative subset of points. K-means spreads those points to represent the overall cloud, so it samples the surface evenly and works well on average.

It has one blind spot. K-means represents the distribution of points, not the topography. It has no way to know which ridges, valleys, or flute margins carry important shape information, so a diagnostic feature can be under-sampled, or left out entirely, even when the sample looks representative.

Anchors are the correction. They are extra points you place by hand, on exactly the features you judge to be important. When you build the template with Use Anchors for Downsampling turned on, GUImorph adds your anchors to the template alongside the k-means points, so those features are guaranteed to be represented. The automatic sample is objective and feature-blind. Anchors are your targeted, subjective additions, the place where your knowledge of the specimen supplements the algorithm.

Do thisOpen the Anchors tab and set the number of anchors. Double-click on each feature the downsample should capture, for example the crest of a ridge or the margin of a flute. Anchors appear in green. Place the same anchors, in the same order, on every specimen.

If your landmark scheme does not use anchors, skip this tab.

The features you consider diagnostic are marked in green, ready to be pulled into the template.
6

Build the surface template (once)

Surface Sliders tab

Surface semilandmarks are a dense set of points spread over the surface between your fixed landmarks. To make them correspond across specimens, you first build a template on one good reference specimen. You do this a single time for the whole study.

Do thisWith the reference specimen loaded and its fixed landmarks placed, open the Surface Sliders tab and set the number of surface points. If you placed anchors, tick Use Anchors for Downsampling. Then click Build Template.

GUImorph reads the mesh, spreads the surface points across it with k-means, adds your fixed landmarks (and anchors, if selected), and saves the result as template.txt in your working folder.

What the template is for

The template records the pattern of surface points on the reference. Every other specimen will receive the same pattern, warped to fit its own surface, so point number 50 means the same location on every specimen. This follows the method of Gunz, Mitteroecker and Bookstein (2005), the same approach geomorph used.

A template.txt file exists in your folder, and the message confirms the template was created.
7

Downsample every specimen against the template

Surface Sliders tab

Now apply the template to each specimen. This is where the corresponding surface points are placed on the other specimens.

Repeat per specimenLoad a specimen. Place its fixed landmarks on the 3D Digitizing tab (and the same anchors on the Anchors tab, if you are using them). Then, on the Surface Sliders tab, click Downsample specimen.

GUImorph warps the template onto this specimen using its landmarks, then places the surface points in their corresponding positions.

Give it a moment when switching specimens

Moving to a new specimen reloads its surface data into the 3D engine. A brief pause after loading or downsampling is normal.

Each specimen ends with surface points that match the template, in corresponding positions.
8

Save each specimen

Save every specimen as you finish it. Do not wait until the end.

MenuFile ▸ Save to DGT…. This writes a .dgt file holding that specimen's landmarks, anchors, curves, and template. Name the file after the specimen so you can tell them apart.
You have one .dgt file per specimen, clearly named.
9

Merge the specimen files

Combine your individual .dgt files into one dataset that holds every specimen together.

MenuFile ▸ Merge DGT Files…, then select all of your .dgt files.

GUImorph checks that the specimens share the same template and curves, so that the surface semilandmarks are comparable, and refuses to merge if they do not match. Then open the merged file with File ▸ Load DGT File… to bring all specimens into one session.

One merged dataset contains all specimens, loaded and ready for the fit.
10

Run the Procrustes fit (GPA)

GPA tab

Generalized Procrustes Analysis removes differences in position, rotation, and size, so that only shape remains. This is the step that makes specimens comparable, and GUImorph runs it through geomorph for you.

Set optionsOn the GPA tab, choose your options. The common ones are Slide semilandmarks on surfaces, Slide semilandmarks on curves, Project into tangent space, and, for speed on large datasets, Parallel processing and Approximate TPS.
Run itClick Compute. GUImorph assembles the coordinates and runs geomorph's gpagen.
Anchors at fit time

The GPA tab also lets you treat anchors as sliding semilandmarks, through Use anchors as surface semilandmarks and Use anchors as curve semilandmarks. This is separate from using anchors to guide the downsample. Leave these off unless your protocol calls for it.

The fit completes without a landmark-count error, and a result is ready to plot.
11

Plot and inspect the results

GPA tab

Use the plot buttons on the same tab to check your work before moving on.

SpecimensPlot Aligned Specimens shows every specimen overlaid, so you can spot one that is misaligned.
VariationPCA (morphospace) places specimens on principal component axes, so you can see how they spread.
MeanPlot Mean Shape shows the average shape. Adjust point size and the mesh options next to it if needed.
Reading the PCA

If one specimen sits far away from all the others in the morphospace, that is usually a mesh-cleaning miss, an unreferenced or origin vertex that survived. Go back, re-clean that mesh, and re-digitize it.

Specimens overlay sensibly, and no point sits impossibly far from the rest.
12

Continue the analysis in geomorph

The fit you just ran is a standard geomorph result, produced by gpagen, so nothing needs converting. Use Save Result on the GPA tab to write it out, and continue in R with the full geomorph toolkit: principal components, allometry, Procrustes ANOVA, and more. Because everything stays in R, there is no export to another program and no format translation.

You have an aligned geomorph result and can carry it into any geomorph analysis.

Part 3 · The .dgt file: your project

When you save your work, GUImorph writes a .dgt file. This is GUImorph's project file: every point you placed, for every specimen, stored in one plain-text file you can save, reopen, and keep working on later. If the .ply scans are the raw material, the .dgt is your saved progress. You can open one in Notepad and read it.

What it holds

A .dgt stores the coordinates of the points you placed, not the mesh. It begins with the parts that are shared across the whole study, then repeats one block for each specimen. Here is the shape of a real file, with notes added:

Curve=3                 # 3 curve sliders; each row is:  start  slider  end
1 2 3                   # slider 2 slides between fixed landmarks 1 and 3
1 6 5
5 4 3

TemplateNumber=1017     # surface template: 1017 reference points
A6_1_clean.ply          # the specimen the template was built from
"V1" "V2" "V3"
-11.68  -13.71  -5.54   # one x y z per row, for all 1017 template points
...

LM3=6                   # ---- specimen block: repeats once per specimen ----
...                     # 6 fixed-landmark rows (x y z)
AC3=10                  # 10 anchors
...                     # 10 anchor rows (x y z)
ID=A6_1_clean.ply       # which .ply scan this specimen is
Template=A6_1_clean.ply # the template it was downsampled against
Surface=1000            # 1000 surface semilandmarks
...                     # 1000 surface rows (x y z)

The two shared sections at the top are the curve rules (Curve=), which say which curve slider sits between which two fixed landmarks, and the surface template (TemplateNumber=), the reference pattern of surface points taken from one specimen. Both are written once, because they are the same for every specimen.

Each specimen block then carries its own fixed landmarks (LM3=, where the 3 means three-dimensional), its anchors (AC3=), the name of the scan it came from (ID=), the template it was downsampled against (Template=), and its surface semilandmarks (Surface=). A study of six specimens produces one .dgt holding all six blocks in sequence.

What it does not hold

The .dgt does not contain the 3D meshes. Those stay in their own .ply files, and the .dgt only records where on each object your points sit, referring to the scan by name in the ID= line. This is why a .dgt stays small while a scan can be large. Think of it as the difference between a tracing and the thing you traced. The .dgt is the tracing.

Keep them together

Store your .ply scans alongside the .dgt. Reopening a session expects the scans to still be findable under the names recorded in the file.

Working with .dgt files

Four File-menu actions cover the life cycle. Save to DGT… writes everything you have placed, all specimens and all point types, into one file. Load DGT File… reads it back and reconstructs the whole session, every specimen with its points where you left them. Add PLY to Current DGT… brings a new scan into the open dataset so you can digitize it alongside the others. Merge DGT Files… combines several .dgt files into one, provided they share the same template, curves, and point counts.

Getting the data into geomorph

The .dgt is GUImorph's own format, for working in GUImorph. To analyze your shapes, run the Procrustes fit on the GPA tab with Compute, which assembles the coordinates and runs geomorph's gpagen for you, then plot or save the result. See step 10.

Part 4 · Troubleshooting

"there is no package called 'geomorph'" (or Rvcg, Morpho, and so on)

A dependency did not install. Install them directly, then load GUImorph again:

install.packages(c("geomorph", "rgl", "Rvcg", "Morpho", "vegan", "tcltk2"))

A loading tkogl2 failed warning at startup

The OpenGL engine did not load. Confirm you are on 64-bit R on Windows: R.version$arch should return "x86_64". Then reinstall the GUImorph package and load it again. The engine is bundled inside the package.

The specimen shows up blank or as a solid black shape

Confirm you are on 64-bit R, then reinstall the GUImorph package and reload it. If a specimen still will not render, try another cleaned .ply to rule out a problem with that particular mesh.

Double-clicking the mesh does not place a point

Check two things. First, make sure you are on the right tab: fixed landmarks go on 3D Digitizing, anchors on Anchors. Second, use a double-click to place, not a single click. A single drag rotates the view.

One specimen is a wild outlier in the PCA

Almost always a cleaning miss. Reopen that mesh, remove unreferenced vertices and any vertex at the origin (0, 0, 0), and digitize it again. See Prepare your meshes.

Merge refuses to combine my files

GUImorph will not merge specimens whose templates or curves differ, because their surface semilandmarks would not be comparable. Make sure every specimen was downsampled against the same template before you save and merge.

The window will not open on my Mac or Linux machine

Expected in this beta. GUImorph 0.9.0 is Windows only. The 3D view depends on an OpenGL component that is not built for macOS or Linux yet, the same limitation that retired geomorph's own digitizer. A cross-platform version is planned.
